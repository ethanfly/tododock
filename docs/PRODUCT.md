# TodoDock 产品规格

状态：产品与工程基线  
工作名称：TodoDock（后续可替换，不影响内部架构）

## 1. 产品愿景

TodoDock 是一个始终离手边很近、但不打扰工作的桌面 Todo 工具。用户可以用全局快捷键在任何应用中快速唤起并记录；需要持续关注时把窗口钉在最前；不需要时把窗口吸附到屏幕边缘并自动隐藏。所有数据默认只保存在本机。

产品优先级依次为：可靠记录、低延迟、低打扰、清晰界面、跨平台一致性。视觉追求克制、轻盈、面向未来，不牺牲可读性和原生桌面习惯。

## 2. 核心原则

- 本地优先：无账号也能完整使用；默认无网络依赖、无遥测、无云端副本。
- 性能优先：冷启动、唤起、输入响应、常驻内存和后台 CPU 都有明确预算。
- 键盘优先但不排斥鼠标：核心流程能在不离开键盘的情况下完成。
- 渐进披露：默认界面只展示当前要做的事，高级设置按需出现。
- 安全可恢复：写入原子化；迁移可回滚；误删和崩溃不能轻易导致数据丢失。
- 能力诚实：平台或桌面环境限制某项能力时，展示原因并提供可用降级方案。

## 3. 首发范围

### 3.1 Todo 管理

- 快速创建、编辑、完成、恢复、归档和删除 Todo。
- 标题适合快速扫描；正文支持 CommonMark 与 GFM 常用语法。
- Markdown 默认采用轻量所见即所得编辑，支持切换源码模式；底层只保存标准 Markdown，禁止正文中的原始 HTML，外部链接需明确打开。
- 支持 deadline；界面始终显示明确时区和“已逾期/即将到期”状态。
- 支持优先级、搜索和按状态/期限筛选。
- 支持键盘排序与拖拽排序；排序结果本地持久化。
- 删除先进入可撤销状态，之后归档/软删除；提供清理入口。

### 3.2 快速记录

- 默认全局快捷键为 `Alt + Space` 老板键：窗口可见时立即隐藏，隐藏时再唤回；用户可在设置中按键录入修改或关闭。
- 托盘「快速新建」仍会唤起并聚焦快速输入框，输入标题后回车即可保存。
- 支持在快速输入中补充 deadline 和 Markdown 正文，不强迫填写完整表单。
- `Esc` 收起窗口；快捷键冲突时不静默失败，显示冲突和修复入口。
- 应用保持单实例；第二次启动聚焦已存在窗口。

### 3.3 窗口行为

- 窗口可自由拖动，位置和尺寸按显示器布局持久化。
- “钉住”控制 always-on-top，状态清晰可见并可随时取消。
- 靠近当前显示器工作区边缘时产生吸附反馈；松手后贴边。
- 启用自动隐藏后，贴边窗口在失焦或短暂延迟后滑出工作区，只保留 6–10px 可唤回把手。
- 指针进入把手、全局快捷键或托盘点击都能唤回；编辑、拖拽、菜单打开或提醒交互时不自动隐藏。
- 支持左、右和上边缘；下边缘默认禁用，避免和系统任务栏、Dock 冲突。
- 显示器断开、分辨率/DPI 变化或工作区变化后，窗口必须被纠正到可见区域。
- “钉住”和“自动隐藏”是正交设置：钉住决定层级，自动隐藏决定贴边后的收起行为。

### 3.4 Deadline 与提醒

- deadline 以 UTC 时间戳存储，以用户当前时区展示。
- 每个 Todo 可设置一次临近提醒；默认提前 15 分钟，可在设置中更改。
- 选择“不提醒”时完全关闭该 Todo 的提前与到期通知；选择“到期时”才发送到期通知。已完成、已归档或已删除的 Todo 不再提醒。
- 提醒必须去重，重启应用不能重复轰炸；修改 deadline 后重新计算。
- 首次保存带提醒的 Todo 时按平台请求通知权限；同一运行周期内拒绝后不重复打扰，设置页保留显式重试入口，并始终提供应用内提醒与设置指引。
- 提供静默时段。静默期间累积的提醒在结束后汇总，避免逐条轰炸。
- 系统休眠恢复后重新扫描漏掉的提醒，并按去重规则补发。

### 3.5 系统集成

- 系统托盘提供显示/隐藏、快速新建、今日任务、设置和退出。
- 关闭主窗口默认最小化到托盘；首次发生时解释此行为，可改为直接退出。
- 开机启动默认关闭，由用户主动开启。
- 提供设置页管理快捷键、通知、静默时段、主题、窗口行为、开机启动、数据目录和可选的禅道任务同步。
- 禅道同步只在用户填写地址/账号并主动点击后发生，通过 REST API 或「我的地盘」任务接口拉取指派任务，合并进本地 Todo；默认不同步、不访问禅道数据库。

### 3.6 数据可控性

- SQLite 数据库位于操作系统应用数据目录，不写入安装目录。
- 支持导出为稳定版本化 JSON；支持导出 Markdown 清单。
- 导入前校验并预览，只合并 Todo 且不改变本机设置，采用事务写入；ID 冲突有确定规则。
- 支持创建一致性备份和从备份恢复；恢复前自动备份当前数据。
- 显示实际数据目录，便于高级用户自行备份。
- 日志不得包含 Todo 标题或正文；诊断包默认只含版本、平台、错误码和脱敏性能数据。

## 4. 容易遗漏但必须处理的事项

- 多显示器与高 DPI：坐标需区分物理/逻辑像素，跨 DPI 拖动不能跳变。
- 夏令时与时区变化：存储 UTC，展示时动态转换；本地输入遇到无效/歧义时间需明确提示。
- Wayland 降级：部分 Linux Wayland 合成器禁止应用精确定位窗口，自动吸附/隐藏可能不可用；仍保留托盘、快捷键或应用内替代入口，并在设置中展示能力状态。
- 通知权限：macOS/Windows/Linux 的授权和实现不同，不能把“API 调用成功”等同于用户看到了通知。
- 可访问性：完整焦点顺序、可见焦点环、语义标签、减少动效模式、颜色对比度和屏幕阅读器文本。
- 输入法：快速输入必须正确处理中文等 IME 组合态，组合过程中回车不能误提交。
- Markdown 安全：不执行原始 HTML/脚本；粘贴与拖入按纯文本处理；链接使用安全打开流程；远程图片不自动联网；编辑器与渲染器延迟加载。
- 数据规模：长列表采用增量查询/虚拟化；全文搜索保留升级到 SQLite FTS5 的迁移路径。
- 生命周期：窗口隐藏不代表进程退出；提醒依赖后台常驻时必须对用户透明。
- 更新与签名：正式发行需要三平台签名/公证策略；自动更新上线前必须支持签名校验和失败回滚。
- 兼容迁移：数据库和导出格式分别版本化，旧版本升级和新版本数据降级风险都需测试。

## 5. 平台能力与降级

### Windows 10/11

目标能力完整：全局快捷键、通知、托盘、置顶、工作区坐标、吸附与贴边隐藏。需验证多屏混合 DPI、任务栏自动隐藏和系统“专注助手”。

### macOS（当前支持版本线）

目标能力完整：全局快捷键、通知、菜单栏托盘、置顶和贴边隐藏。需处理辅助权限/通知权限提示、Notch/菜单栏安全区、全屏 Space 和应用激活规则。正式包需签名与公证。

### Linux X11

在常见窗口管理器上提供完整能力；托盘和通知依赖桌面环境实现，需检测可用性。

### Linux Wayland

Todo、Markdown、本地存储、提醒和大部分托盘/快捷键功能继续工作。若合成器不允许获取或设置绝对窗口位置，则禁用自动吸附/贴边隐藏，并使用显式收起、托盘和快捷键唤回。UI 必须说明这是平台限制。

## 6. 视觉与交互方向

- 窗口采用紧凑卡片式层级、柔和半透明表面和少量强调色；避免装饰性噪音。
- 字体依赖系统字体栈，正文优先可读性；支持系统深浅主题并允许手动覆盖。
- 动效只解释状态变化，常规 120–180ms；遵循 `prefers-reduced-motion`。
- 到期风险同时使用文字、图标和颜色表达，不能只依赖红/绿色。
- 默认窗口建议 420×640，最小 340×420；布局能在窄窗口稳定工作。

## 7. 性能预算

- 已安装发布包暖启动到可输入：目标低于 500ms，P95 低于 800ms（基准机器单独记录）。
- 全局快捷键到输入框可输入：目标低于 150ms，P95 低于 250ms。
- 输入与列表常规交互：主线程长任务不超过 50ms；输入反馈小于一帧。
- 1 万条 Todo 下搜索/筛选：目标 P95 低于 100ms。
- 隐藏空闲时后台 CPU：长期平均低于 0.2%；提醒调度不得轮询高频唤醒。
- 常驻内存：首发以低于 120MB 为工程目标，按三平台分别记录。

预算是验收目标，不是未经测量的承诺。发布构建需留下可复现的测量脚本和结果。

## 8. 首发非目标

- 云同步、账号系统、多人协作和移动端。
- 私有富文本文件格式、多人协同编辑和任意嵌入内容；所见即所得层始终以 Markdown 为唯一持久格式。
- 复杂项目管理（甘特图、团队看板、工时）。
- 可执行插件或第三方脚本。

数据模型和命令边界需为未来的标签、子任务、重复任务、自然语言日期输入和可选端到端加密同步保留演进空间，但不让这些能力拖慢首发。

## 9. 验收标准

只有下列证据全部成立，持久目标才可判定完成：

1. 三个平台的源码构建配置存在，Windows 至少完成真实打包运行验证；macOS/Linux 使用 CI 原生 runner 构建，并记录平台特有手工验收清单。
2. 核心 Todo、Markdown、deadline、提醒、全局快捷键、托盘、置顶、拖动、吸附与自动隐藏都有自动化测试或可复现手工验证证据。
3. 数据库迁移、崩溃恢复、提醒去重、休眠恢复、导入导出和备份恢复有测试。
4. 快捷键冲突、通知权限拒绝、Wayland/无托盘等能力缺失有明确且可操作的降级界面。
5. `lint`、TypeScript 检查、Rust 格式与 lint、前后端测试、生产构建全部通过。
6. 性能预算有实际基准数据；未达项必须明确记录，不能以“预期性能好”替代。
7. 数据仅在本地，网络访问和日志内容经过审计；Markdown 渲染不执行不可信代码。
8. README 包含开发、测试、构建、数据位置、备份恢复和平台限制说明。
